## What is Replay QA?

Replay QA is an autonomous QA product that tests web applications without requiring a test suite,
QA team, or manual configuration. Give it a URL or connect a GitHub repository and it explores
the app, writes and runs its own Playwright tests, records every session with a deterministic
time-travel debugger, and files detailed bug reports — including root cause analysis and a
suggested fix ready for a coding agent to apply.

It is built by Replay.io, the company behind the Replay time-travel debugging platform. Replay QA
is used by engineering teams and software factories running autonomous coding pipelines at scale.

## Core Capabilities

### Functional QA
Replay QA maps user journeys autonomously, runs them in a Chromium browser, records every
session, and analyzes failures. It catches:
- Deep runtime bugs: React component failures, state mutations, race conditions, async timing
- UI glitches: layout shifts, broken buttons, elements hidden behind overlays
- Accessibility failures: WCAG contrast violations, missing ARIA labels, keyboard traps
- Performance problems: slow network calls, render-blocking resources, long tasks

### Security Scan (AI Pentesting)
Replay QA offers a security pass that covers the full scope of a penetration test:
- Injection vulnerabilities (SQL, XSS, command injection)
- Broken access control
- Weak authentication
- Insecure API behavior
- Business logic gaps: IDOR (Insecure Direct Object Reference), cross-tenant data exposure
It reasons about how the application is supposed to work, which allows it to surface
authorization and logic flaws that generic scanners miss.

### Scheduled Test Runs
Teams can configure automated runs on a daily or weekly schedule. A common pattern is an
overnight run that delivers a fresh batch of prioritized issues each morning, ready for coding
agents or software factories to process.

### Multi-environment Support
A single Replay QA project can target multiple environments: dev, staging, production, or
localhost (via reverse proxy). Environments can be switched in the project dashboard or managed
programmatically via the REST API.

### Software Factory Integration
Replay QA is designed to plug into autonomous coding pipelines as a runtime verification layer.
Trigger runs via REST API from your own orchestration, receive structured bug reports your agents
can act on, and give your human reviewers a recording of every failure rather than a diff to
guess from. Used by teams shipping more pull requests than anyone can review by hand.

## How It Works (6 steps)

1. Start — Paste a URL or connect a GitHub repo. No setup beyond that.
2. Exploration — Agents map the app, discover user journeys, and identify flows worth testing.
3. Testing — A swarm of agents runs all journeys in parallel in a Chromium browser, recording
   every session deterministically (every DOM mutation, network call, and JS frame captured).
4. Analysis — For failed tests, agents time-travel through recordings to find root cause. They
   read what the app did at runtime, not what the code says it should do.
5. Reports — Each bug comes with: a video recording of the failure, annotated screenshots,
   root cause analysis (with confidence score), and a suggested fix.
6. The Loop — Apply fixes, ship, re-run. Same journeys verify the fix and catch regressions.
   New app changes are detected and tested automatically.

## Integrations

- **GitHub** — Install the Replay QA GitHub app on any repo. Triggers on push to main, PRs, or
  a schedule. PR runs post root cause + suggested fix as a PR comment.
- **Issue trackers** — Webhook integration with GitHub Issues, Linear, Jira, or any HTTP endpoint.
  Configurable: file manually, on confirmed bugs only, or for all reports.
- **REST API** — Full API at https://qa.replay.io/api/v1 (OpenAPI spec at /api/v1/openapi.json).
  Trigger runs, switch environments, enable Security Scan, retrieve results, and mark bugs and
  security findings resolved.
- **Replay MCP** — Agents can pull structured bug reports and time-travel debug their own failures
  via the Replay MCP server. On Web Debug Bench (Apr 2026; 177 hard, realistic bugs in agent-built
  web apps, https://blog.replay.io/web-debug-bench), an agent with runtime access solved 76%; the
  same agent reading code alone solved 61%.
- **Reverse proxy** — Test localhost or private-network apps without exposing them publicly.

## Use Cases

- **Web application testing service** (https://replay.io/web-application-testing) — Test a web
  app end to end from just a URL or GitHub repo: functional, UI, accessibility, and performance
  bugs, plus an optional security pass. Replay QA is an autonomous product, not a managed service
  with human testers.
- **Continuous testing platform** (https://replay.io/continuous-testing) — Run Replay QA on every
  push, pull request, or schedule via the GitHub app or REST API. The same journeys re-run to
  verify fixes and catch regressions, with reports sent to GitHub Issues, Linear, or Jira.
- **Automated QA testing tool** (https://replay.io/automated-qa-testing) — Automates the whole QA
  loop: exploration, writing and running Playwright tests, root cause analysis, and a suggested
  fix for a coding agent.

## Comparisons

Overview: https://replay.io/compare. Competitor details below are from each vendor's public site
and documentation, verified 2026-10-14 to 2026-10-22. Replay QA tests web apps only; tools listed with native mobile
support cover something Replay QA does not.

- **Momentic** (https://replay.io/compare/momentic) — Alternative. Momentic's Mo agent explores
  from a brief (target, scope, accounts, test data) and Momentic also offers plain-English YAML
  tests and native iOS/Android testing. Replay QA starts from a URL, records every session
  deterministically, and includes root cause and a suggested fix in each report.
- **Ranger** (https://replay.io/compare/ranger) — Alternative. Ranger verifies scenarios written by
  your coding agent, locally, before the agent finishes a feature. Replay QA explores the whole app
  and runs on every PR, push or schedule.
- **Tester Army** (https://replay.io/compare/tester-army) — Alternative. Plain-English test runs and
  goal-driven discovery runs on web and native mobile, with video, screenshots and logs. Replay QA
  needs no tests and adds root cause and a suggested fix.
- **PostHog self-driving** (https://replay.io/compare/posthog) — Different stage. PostHog finds
  issues in production user data and opens fix PRs. Replay QA tests before release and needs no
  users. Many teams use both.
- **QA Wolf** (https://replay.io/compare/qa-wolf) — Works alongside. QA Wolf builds and maintains
  Playwright and Appium regression suites, self-serve or managed. Replay QA explores beyond the
  suite and diagnoses app bugs with a suggested code fix.
- **Meticulous** (https://replay.io/compare/meticulous) — Works alongside. Meticulous generates
  visual regression tests from recorded sessions and diffs every PR. Replay QA explores the app
  for bugs without a recorder script.
- **BrowserStack** (https://replay.io/compare/browserstack) and **Sauce Labs**
  (https://replay.io/compare/sauce-labs) — Work alongside. Real-device clouds for running your test
  suites, with AI authoring and failure analysis. Replay QA explores web apps without a suite and
  diagnoses from a deterministic recording.
- **Playwright** (https://replay.io/compare/playwright) — Replay QA is built on Playwright. Playwright
  Test Agents' healer repairs test code and marks a test test.fixme() when the app looks broken;
  Replay QA reports that bug with root cause and a suggested fix.
- **Qodo** (https://replay.io/compare/qodo) — Works alongside. Qodo is AI code review and
  governance: it reviews each PR against the whole repository and can apply fixes. Replay QA tests
  the running app in a browser and finds bugs that only appear at runtime.
- **Your coding agent** (https://replay.io/compare/coding-agents) — Claude Code or Codex can check a
  flow in a live browser. Replay QA tests every journey systematically, on every PR or schedule,
  keeps a deterministic recording of each failure, and hands the agent root cause via Replay MCP.
